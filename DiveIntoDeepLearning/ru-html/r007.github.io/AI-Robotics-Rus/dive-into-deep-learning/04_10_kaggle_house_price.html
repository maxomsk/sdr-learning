4.10.1 Загрузка и кэширование набора данных

На протяжении всей книги мы будем загружать различные наборы данных и обучать и тестировать на них модели. Здесь мы реализуем несколько функций, которые упрощают загрузку данных. Сначала создадим словарь DATA_HUB, который сопоставляет строковое имя набора данных с парой значений: URL набора данных и хеш-суммой SHA-1 для проверки целостности файла. Все такие наборы данных размещены на сайте по адресу DATA_URL.

import os
import requests
import zipfile
import tarfile
import hashlib

#@save
DATA_HUB = dict()
DATA_URL = 'http://d2l-data.s3-accelerate.amazonaws.com/'

Функция download ниже загружает набор данных, кэширует его в локальном каталоге (по умолчанию ../data) и возвращает имя загруженного файла. Если файл набора данных уже есть в каталоге кэша и его SHA-1 совпадает со значением из DATA_HUB, будет использован кэшированный файл, чтобы не скачивать его повторно.

def download(name, cache_dir=os.path.join('..', 'data')):  #@save
    """Скачать файл из DATA_HUB и вернуть локальное имя файла"""
    assert name in DATA_HUB, f"{name} отсутствует в {DATA_HUB}"
    url, sha1_hash = DATA_HUB[name]
    os.makedirs(cache_dir, exist_ok=True)
    fname = os.path.join(cache_dir, url.split('/')[-1])
    if os.path.exists(fname):
        sha1 = hashlib.sha1()
        with open(fname, 'rb') as f:
            while True:
                data = f.read(1048576)
                if not data:
                    break
                sha1.update(data)
        if sha1.hexdigest() == sha1_hash:
            return fname  # Попадание в кэш
    print(f'Загрузка {fname} из {url}...')
    r = requests.get(url, stream=True, verify=True)
    with open(fname, 'wb') as f:
        f.write(r.content)
    return fname

Нам также понадобятся две вспомогательные функции: одна скачивает и распаковывает zip- или tar-архив, а другая скачивает в кэш все наборы данных из DATA_HUB, используемые в книге.

def download_extract(name, folder=None):  #@save
    """Скачать и распаковать zip/tar-файл"""
    fname = download(name)
    base_dir = os.path.dirname(fname)
    data_dir, ext = os.path.splitext(fname)
    if ext == '.zip':
        fp = zipfile.ZipFile(fname, 'r')
    elif ext in ('.tar', '.gz'):
        fp = tarfile.open(fname, 'r')
    else:
        assert False, 'Распаковывать можно только zip/tar-файлы'
    fp.extractall(base_dir)
    return os.path.join(base_dir, folder) if folder else data_dir

def download_all():  #@save
    """Скачать все файлы из DATA_HUB"""
    for name in DATA_HUB:
        download(name)

4.10.4 Предобработка данных

Как уже сказано, данные имеют разные типы. Прежде чем начать моделирование, нужно их предобработать. Сначала заменим все пропущенные значения средним значением соответствующего признака. Затем, чтобы привести все признаки к единому масштабу, стандартизуем данные, приводя признаки к нулевому среднему и единичной дисперсии:

x←σx−μ​,

где μ и σ — среднее значение и стандартное отклонение соответственно. Теперь признаки имеют нулевое среднее и единичную дисперсию, то есть E[σx−μ​]=σμ−μ​=0 и E[(x−μ)2]=(σ2+μ2)−2μ2+μ2=σ2. Интуитивно стандартизация данных полезна по двум причинам. Во-первых, это упрощает оптимизацию. Во-вторых, поскольку мы не знаем, какие признаки связаны между собой, мы не хотим, чтобы штраф назначал коэффициент одному признаку больше, чем другим.

# Если тестовые данные недоступны, среднее и стандартное отклонение можно вычислить по обучающим данным
numeric_features = all_features.dtypes[all_features.dtypes != 'object'].index
all_features[numeric_features] = all_features[numeric_features].apply(
    lambda x: (x - x.mean()) / (x.std()))
# После стандартизации все средние равны нулю, поэтому пропуски можно заменить нулём
all_features[numeric_features] = all_features[numeric_features].fillna(0)

Далее обработаем дискретные значения. К ним относятся такие признаки, как «MSZoning». Мы заменяем их прямым кодированием (one-hot), тем же способом, что и при преобразовании многоклассовых меток в векторы ранее (см. раздел 3.4.1). Например, признак «MSZoning» содержит значения «RL» и «Rm». Мы создадим два новых индикаторных признака «MSZoning_RL» и «MSZoning_RM» со значениями 0 или 1. Согласно прямому кодированию, если исходное значение «MSZoning» — «RL», то «MSZoning_RL» равно 1, а «MSZoning_RM» равно 0. Пакет pandas делает это за нас автоматически.

# Dummy_na=True считает «na» (пропущенное значение) допустимым значением признака и создаёт для него индикаторный признак

4.10.5 Обучение

Для начала обучим линейную модель с квадратичной функцией потерь. Линейная модель вряд ли позволит выиграть соревнование, но она служит проверкой здравого смысла: есть ли в данных осмысленная информация. Если здесь мы не сможем работать лучше случайного угадывания, скорее всего, в обработке данных есть ошибка. Если всё пойдёт хорошо, линейная модель будет служить базовой (baseline) моделью, и мы поймём, насколько лучшая модель превосходит простую.

Цены на жильё, как и цены акций, нас интересуют в относительных величинах, а не в абсолютных. Поэтому мы больше заботимся об относительной ошибке yy−y^​​, чем об абсолютной ошибке y−y^​. Например, если мы оцениваем стоимость дома в сельской местности Огайо и ошибаемся на 100 000 долларов, при том что типичный дом там стоит 125 000 долларов, то модель, скорее всего, работает плохо. С другой стороны, та же ошибка в 100 000 долларов для особняка в районе Калифорнии, где медианная цена превышает 4 миллиона долларов, может означать хороший прогноз.

Один из способов решить эту проблему — измерять расхождение логарифмом цены. Фактически именно эту метрику ошибки официально использует соревнование для оценки качества решений. Условие ∣logy−logy^​∣≤δ равносильно e−δ≤yy^​​≤eδ. Поэтому среднеквадратичная ошибка между логарифмом предсказанной цены и логарифмом истинной метки:

n1​i=1∑n​(logyi​−logy^​i​)2​.

MXNet:

def log_rmse(net, features, labels):
    # Чтобы стабилизировать значение при взятии логарифма, значения меньше 1 заменяем на 1
    clipped_preds = np.clip(net(features), 1, float('inf'))
    return np.sqrt(2 * loss(np.log(clipped_preds), np.log(labels)).mean())

PyTorch:

def log_rmse(net, features, labels):

    clipped_preds = torch.clamp(net(features), 1, float('inf'))
    rmse = torch.sqrt(loss(torch.log(clipped_preds),
                           torch.log(labels)))

TensorFlow:

def log_rmse(y_true, y_pred):

PaddlePaddle:

4.10.6 K-кратная перекрёстная проверка

В разделе, посвящённом выбору модели (раздел 4.4), мы описали K-кратную перекрёстную проверку. Она помогает выбирать модель и настраивать гиперпараметры. Сначала определим функцию, которая возвращает данные i-го фолда при K-кратной перекрёстной проверке. Конкретно, она выбирает i-й фрагмент в качестве проверочных данных, а остальные части — в качестве обучающих. Заметим, что это не самый эффективный способ работы с данными: при гораздо большем наборе данных могут подойти другие решения.

def get_k_fold_data(k, i, X, y):
    assert k > 1
    fold_size = X.shape[0] // k
    X_train, y_train = None, None
    for j in range(k):
        idx = slice(j * fold_size, (j + 1) * fold_size)
        X_part, y_part = X[idx, :], y[idx]
        if j == i:
            X_valid, y_valid = X_part, y_part
        elif X_train is None:
            X_train, y_train = X_part, y_part
        else:
            X_train = d2l.concat([X_train, X_part], 0)
            y_train = d2l.concat([y_train, y_part], 0)
    return X_train, y_train, X_valid, y_valid

Когда мы обучили модель K раз в K-кратной перекрёстной проверке, возвращаем среднее значение ошибок обучения и проверки.

def k_fold(k, X_train, y_train, num_epochs, learning_rate, weight_decay,
           batch_size):
    train_l_sum, valid_l_sum = 0, 0
    for i in range(k):
        data = get_k_fold_data(k, i, X_train, y_train)
        net = get_net()
        train_ls, valid_ls = train(net, *data, num_epochs, learning_rate,
                                   weight_decay, batch_size)
        train_l_sum += train_ls[-1]
        valid_l_sum += valid_ls[-1]
        if i == 0:
            d2l.plot(list(range(1, num_epochs + 1)), [train_ls, valid_ls],
                     xlabel='эпоха', ylabel='rmse', xlim=[1, num_epochs],
                     legend=['обучение', 'проверка'], yscale='log')
        print(f'Фолд {i + 1}, log rmse на обучении {float(train_ls[-1]):f}, '
              f'log rmse на проверке {float(valid_ls[-1]):f}')
    return train_l_sum / k, valid_l_sum / k

4.10.7 Выбор модели

В этом примере мы выбираем набор ненастроенных гиперпараметров и оставляем читателю возможность улучшить модель. Поиск хорошего набора гиперпараметров может занять время — в зависимости от того, сколько переменных мы оптимизируем. При достаточно большом наборе данных и разумно заданных гиперпараметрах K-кратная перекрёстная проверка обычно даёт устойчивые результаты при повторных запусках. Однако если мы опробуем неудачные гиперпараметры, проверочная ошибка может перестать отражать истинную ошибку.

k, num_epochs, lr, weight_decay, batch_size = 5, 100, 5, 0, 64
train_l, valid_l = k_fold(k, train_features, train_labels, num_epochs, lr,
                          weight_decay, batch_size)
print(f'{k}-кратная проверка: средняя log rmse на обучении: {float(train_l):f}, '
      f'средняя log rmse на проверке: {float(valid_l):f}')

Обратите внимание: иногда ошибка обучения для набора гиперпараметров может быть очень низкой, а ошибка K-кратной перекрёстной проверки — намного выше. Это указывает на переобучение модели. На протяжении всего обучения мы хотим следить за двумя величинами: ошибкой обучения и ошибкой проверки. Небольшое переобучение может говорить о том, что имеющихся данных достаточно для более мощной модели. Сильное переобучение, напротив, может означать, что стоит воспользоваться методами регуляризации.

4.10.8 Отправка прогнозов на Kaggle

Теперь, когда мы знаем, какие гиперпараметры выбрать, можно обучить модель на всех данных (а не только на 1 − 1/K от данных, как в перекрёстной проверке). Затем полученную модель можно применить к тестовому набору. Сохранение прогнозов в CSV-файл упрощает отправку результатов на Kaggle.

def train_and_pred(train_features, test_features, train_labels, test_data,
                   num_epochs, lr, weight_decay, batch_size):
    net = get_net()
    train_ls, _ = train(net, train_features, train_labels, None, None,
                        num_epochs, lr, weight_decay, batch_size)
    d2l.plot(np.arange(1, num_epochs + 1), [train_ls], xlabel='эпоха',
             ylabel='log rmse', xlim=[1, num_epochs], yscale='log')
    print(f'log rmse на обучении: {float(train_ls[-1]):f}')
    # Применить сеть к тестовому набору
    preds = d2l.numpy(net(test_features))
    # Преобразовать формат для экспорта в Kaggle
    test_data['SalePrice'] = pd.Series(preds.reshape(1, -1)[0])
    submission = pd.concat([test_data['Id'], test_data['SalePrice']], axis=1)
    submission.to_csv('submission.csv', index=False)

Если прогнозы на тестовом наборе похожи на прогнозы, полученные во время K-кратной перекрёстной проверки, пора загружать их на Kaggle. Следующий код создаст файл submission.csv.

train_and_pred(train_features, test_features, train_labels, test_data,
               num_epochs, lr, weight_decay, batch_size)

Далее прогнозы можно отправить на Kaggle и посмотреть, как они соотносятся с реальными ценами домов (метками) на тестовом наборе. Процедура очень простая.

  • Войдите на сайт Kaggle и откройте страницу соревнования по прогнозированию цен на жильё.
  • Нажмите кнопку «Submit Predictions» или «Late Submission» (на момент написания этих строк она находится справа).
  • Нажмите кнопку «Upload Submission File» в пунктирной рамке внизу страницы и выберите файл с прогнозами.
  • Нажмите кнопку «Make Submission» внизу страницы, чтобы увидеть результат.

Резюме

  • Реальные данные обычно содержат смесь разных типов данных, их нужно предобработать.
  • Распространённые приёмы предобработки: приведение вещественных данных к нулевому среднему и единичной дисперсии; замена пропущенных значений средним.
  • Преобразование категориальных признаков в индикаторные позволяет трактовать их как one-hot вектор.
  • Для выбора модели и настройки гиперпараметров можно использовать K-кратную перекрёстную проверку.
  • Логарифм полезен, когда важна относительная ошибка.
