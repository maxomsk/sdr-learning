11.5 Минибатчевый стохастический градиентный спуск

До сих пор в градиентных методах обучения мы встречались с двумя крайними случаями: в разделе 11.3 для вычисления градиента и обновления параметров использовался полный набор данных, а в разделе 11.4 на каждом шаге обрабатывался один обучающий пример. У обоих подходов есть свои недостатки: градиентный спуск не слишком «эффективен по данным», когда данные очень похожи друг на друга. А стохастический градиентный спуск не особенно «эффективен по вычислениям», поскольку процессоры CPU и GPU не могут полностью использовать векторизацию. Это подсказывает, что между ними может существовать компромисс — и это и есть минибатчевый стохастический градиентный спуск (minibatch gradient descent).

11.5.1 Векторизация и кэш

Ключевой аргумент в пользу минибатчей — вычислительная эффективность. Это особенно наглядно видно при параллельных вычислениях на нескольких GPU и нескольких серверах. В этом случае каждому GPU нужно передать хотя бы одно изображение. При 8 GPU на каждом сервере и 16 серверах мы получаем минибатч размером 128.

Когда речь идёт об одном GPU или даже CPU, всё устроено тоньше: у этих устройств есть несколько типов памяти, обычно несколько типов вычислительных блоков и разные ограничения пропускной способности между ними. Например, у CPU есть небольшое число регистров, кэши L1 и L2, а также кэш L3, общий для разных ядер процессора. С ростом объёма кэша растёт и его задержка, а пропускная способность падает. Можно сказать, что процессор способен выполнять гораздо больше операций, чем может обеспечить интерфейс основной памяти.

Во-первых, 2-гигагерцовый CPU с 16 ядрами и векторизацией AVX-512 может обработать до 2⋅109⋅16⋅32=1012 байт в секунду. В то же время производительность GPU легко превышает эту величину в 100 раз. С другой стороны, пропускная способность типичного серверного процессора среднего класса вряд ли превышает 100 Гбит/с, то есть меньше одной десятой того, что требуется для полной загрузки процессора. Более того, не все обращения к памяти одинаково выгодны: интерфейс памяти обычно имеет ширину 64 бита или больше (например, у GPU — до 384 бит). Поэтому чтение одного байта приводит к накладным расходам, поскольку фактически читается более широкий блок.

Во-вторых, первое обращение к памяти сопряжено со значительными накладными расходами, тогда как последовательный доступ (sequential access) или пакетное чтение (burst read) обходится относительно дёшево. Подробнее об этом можно прочитать в статье Википедии об иерархии кэшей.

Смягчить эти ограничения позволяет достаточно быстрая иерархия кэшей процессора, которая снабжает процессор данными. Именно эта идея стоит за пакетной обработкой в глубоком обучении. Простой пример — умножение матриц. Пусть A=BC. Существует много способов вычислить A. Например, можно попробовать следующие:

  1. Вычислить Aij​=Bi,:​C:,j⊤​, то есть поэлементно через скалярные произведения.
  2. Вычислить A:,j​=BC:,j⊤​, то есть по одному столбцу за раз. Аналогично можно вычислять A по одной строке Ai,:​.
  3. Просто вычислить A=BC.
  4. Разбить B и C на блочные матрицы меньшего размера и вычислять A по одному блоку за раз.

Если использовать первый вариант, то при каждом вычислении элемента Aij​ строку и столбец нужно копировать в CPU. Ещё хуже то, что поскольку элементы матрицы выровнены последовательно, при чтении из памяти приходится обращаться ко многим несмежным позициям в обоих векторах. Второй вариант относительно выгоднее: мы можем держать столбец C:,j​ в кэше CPU, пока проходим по B. Это вдвое снижает требования к пропускной способности памяти и соответственно ускоряет доступ. Третий вариант на первый взгляд самый предпочтительный, однако большинство матриц, скорее всего, целиком не поместятся в кэш. Четвёртый вариант даёт практически полезное решение: можно переносить в кэш блоки матриц и перемножать их локально. Посмотрим, насколько эффективны эти операции на практике.

Помимо эффективности вычислений, существенные накладные расходы создают сам Python и фреймворк глубокого обучения. Напомним, что каждый раз, когда мы выполняем код, интерпретатор Python отправляет фреймворку глубокого обучения команду, которая должна добавить операцию в вычислительный граф и обработать её при планировании выполнения. Такие накладные расходы могут быть весьма ощутимыми. Итак, лучше всего использовать векторизацию (и матрицы).

11.5.2 Минибатчи

Ранее мы без раздумий считывали минибатчи данных, а не отдельные наблюдения, чтобы обновлять параметры. Теперь кратко объясним причины. Обработка одного наблюдения требует выполнения множества отдельных умножений матрицы на вектор (или даже вектора на вектор), что довольно затратно и сопряжено с большими накладными расходами со стороны фреймворка. Это справедливо как для вычисления градиентов при обновлении параметров, так и для предсказания с помощью нейронной сети. То есть каждое выполнение w←w−ηt​gt​ обходится дорого, где

gt​=∂w​f(xt​,w).

Мы можем повысить вычислительную эффективность этой операции, применив её к минибатчу наблюдений. То есть вместо градиента gt​ для одного наблюдения мы используем градиент для минибатча:

gt​=∂w​∣Bt​∣1​i∈Bt​∑​f(xi​,w).

Посмотрим, как это влияет на статистические свойства gt​. Поскольку xt​ и все элементы минибатча Bt​ выбираются случайно из обучающего набора, математическое ожидание градиента остаётся неизменным. С другой стороны, дисперсия существенно уменьшается. Поскольку градиент минибатча состоит из b:=∣Bt​∣ независимых градиентов, которые усредняются, его стандартное отклонение уменьшается в b−21​ раз. Это само по себе хорошо, поскольку обновление становится ближе к полному градиенту.

Интуитивно понятно, что выбор большого минибатча Bt​ обычно оправдан. Однако через некоторое время дополнительное уменьшение стандартного отклонения становится незначительным по сравнению с линейным ростом вычислительных затрат. На практике мы выбираем минибатч достаточно большим, чтобы обеспечить хорошую вычислительную эффективность, но при этом он всё ещё помещался в память GPU. Далее рассмотрим код, реализующий эту идею. Мы выполним то же самое умножение матриц, но теперь разобьём его на «минибатчи» по 64 столбца.

timer.start()

Очевидно, что вычисления на минибатчах практически так же эффективны, как и на полной матрице. Стоит отметить, что в разделе 7.5 мы использовали вид регуляризации, который в значительной степени зависит от дисперсии внутри минибатча. По мере её роста дисперсия уменьшается, и вместе с этим исчезает польза от шума, который вносит пакетная нормализация. Подробности о том, как пересчитывать масштаб и вычислять соответствующие величины, см. в работе (Ioffe, 2017).

11.5.4 Реализация с нуля

Минибатчевый стохастический градиентный спуск уже был реализован в разделе 3.2. Здесь мы сделаем его входные параметры более общими, главным образом для того, чтобы другие алгоритмы оптимизации, описанные в этой главе, могли использовать те же входы. А именно, мы добавляем входное состояние states и помещаем гиперпараметры в словарь hyperparams. Кроме того, мы будем усреднять потери по отдельным минибатчам в функции обучения, поэтому градиенты в алгоритме оптимизации не нужно делить на размер батча.

MXNet:

def sgd(params, states, hyperparams):
    for p in params:
        p[:] -= hyperparams['lr'] * p.grad

PyTorch:

def sgd(params, states, hyperparams):
    for p in params:
        p.data.sub_(hyperparams['lr'] * p.grad)
        p.grad.data.zero_()

TensorFlow:

def sgd(params, grads, states, hyperparams):
    for param, grad in zip(params, grads):
        param.assign_sub(hyperparams['lr']*grad)

PaddlePaddle:

def sgd(params, states, hyperparams):
    a = []
    with paddle.no_grad():
        for p in params:
            p = p - hyperparams['lr'] * p.grad
            p.stop_gradient = False
            a.append(p)
        return a

Ниже реализуем общую функцию обучения, которую будем использовать для других алгоритмов оптимизации в этой главе. Она инициализирует модель линейной регрессии, а затем позволяет обучать модель с помощью минибатчевого стохастического градиентного спуска и других алгоритмов, которые описаны в последующих подразделах.

MXNet:

#@save
def train_ch11(trainer_fn, states, hyperparams, data_iter,
               feature_dim, num_epochs=2):
    # Инициализация модели
    w = np.random.normal(scale=0.01, size=(feature_dim, 1))
    b = np.zeros(1)
    w.attach_grad()
    b.attach_grad()
    net, loss = lambda X: d2l.linreg(X, w, b), d2l.squared_loss
    # Обучение модели
    animator = d2l.Animator(xlabel='эпоха', ylabel='потери',
                            xlim=[0, num_epochs], ylim=[0.22, 0.35])
    n, timer = 0, d2l.Timer()
    for _ in range(num_epochs):
        for X, y in data_iter:
            with autograd.record():
                l = loss(net(X), y).mean()
            l.backward()
            trainer_fn([w, b], states, hyperparams)
            n += X.shape[0]
            if n % 200 == 0:
                timer.stop()
                animator.add(n/X.shape[0]/len(data_iter),
                             (d2l.evaluate_loss(net, data_iter, loss),))
                timer.start()
    print(f'потери: {animator.Y[0][-1]:.3f}, {timer.avg():.3f} сек/эпоху')
    return timer.cumsum(), animator.Y[0]

PyTorch:

#@save
def train_ch11(trainer_fn, states, hyperparams, data_iter,
               feature_dim, num_epochs=2):
    # Инициализация модели
    w = torch.normal(mean=0.0, std=0.01, size=(feature_dim, 1),
                     requires_grad=True)
    b = torch.zeros((1), requires_grad=True)
    net, loss = lambda X: d2l.linreg(X, w, b), d2l.squared_loss
    # Обучение модели

def train_sgd(lr, batch_size, num_epochs=2):
    data_iter, feature_dim = get_data_ch11(batch_size)
    return train_ch11(
        sgd, None, {'lr': lr}, data_iter, feature_dim, num_epochs)

gd_res = train_sgd(1, 1500, 10)

Когда размер минибатча равен 1, оптимизация использует стохастический градиентный спуск. Для упрощения реализации мы выбрали очень маленькую скорость обучения. В эксперименте со стохастическим градиентным спуском параметры модели обновляются каждый раз, когда обработан один пример. В данном случае это соответствует 1500 обновлениям за эпоху. Видно, что снижение значения целевой функции становится довольно пологим уже после одной эпохи. Хотя оба примера обрабатывают 1500 примеров за одну эпоху, стохастическому градиентному спуску требуется больше времени на эпоху. Это объясняется тем, что стохастический градиентный спуск чаще обновляет параметры и обрабатывать отдельные наблюдения менее эффективно.

sgd_res = train_sgd(0.005, 1)

Наконец, при размере минибатча 100 мы используем минибатчевый стохастический градиентный спуск. Время на эпоху здесь меньше, чем у стохастического и пакетного градиентного спуска.

mini1_res = train_sgd(.4, 100)

Если уменьшить размер минибатча до 10, время на эпоху снова вырастет, поскольку каждая порция работы выполняется менее эффективно.

mini2_res = train_sgd(.05, 10)

Теперь сравним время и потери для первых четырёх экспериментов. Видно, что хотя по числу обработанных примеров стохастический градиентный спуск сходится быстрее градиентного спуска, для достижения того же значения потерь ему требуется больше времени, поскольку вычисление градиента по одному примеру не так эффективно. Минибатчевый стохастический градиентный спуск позволяет сбалансировать скорость сходимости и вычислительную эффективность. Минибатч размером 10 эффективнее стохастического градиентного спуска; минибатч размером 100 даже по времени выполнения опережает градиентный спуск.

#@save
def train_concise_ch11(trainer_fn, hyperparams, data_iter, num_epochs=4):
    # Инициализация модели
    net = nn.Sequential(nn.Linear(5, 1))
    def init_weights(m):
        if type(m) == nn.Linear:
            torch.nn.init.normal_(m.weight, std=0.01)
    net.apply(init_weights)

    optimizer = trainer_fn(net.parameters(), **hyperparams)
    loss = nn.MSELoss(reduction='none')
    animator = d2l.Animator(xlabel='эпоха', ylabel='потери',
                            xlim=[0, num_epochs], ylim=[0.22, 0.35])
    n, timer = 0, d2l.Timer()
    for _ in range(num_epochs):
        for X, y in data_iter:
            optimizer.zero_grad()
            out = net(X)
            y = y.reshape(out.shape)
            l = loss(out, y)
            l.mean().backward()
            optimizer.step()
            n += X.shape[0]
            if n % 200 == 0:
                timer.stop()

def train_concise_ch11(trainer_fn, hyperparams, data_iter, num_epochs=2):
    # Инициализация модели
    net = tf.keras.Sequential()
    net.add(tf.keras.layers.Dense(1,

Резюме

  • Векторизация делает код более эффективным благодаря сокращению накладных расходов фреймворка глубокого обучения, лучшему размещению данных в памяти и использованию кэшей CPU и GPU.
  • Существует компромисс между «статистической эффективностью» стохастического градиентного спуска и «вычислительной эффективностью» пакетной обработки больших объёмов данных сразу. Минибатчевый стохастический градиентный спуск даёт то и другое: вычислительную и статистическую эффективность.
  • В минибатчевом стохастическом градиентном спуске мы обрабатываем батчи, полученные из случайной перестановки обучающих данных (то есть каждое наблюдение обрабатывается один раз, но в случайном порядке).
  • Снижение скорости обучения в ходе обучения помогает обучению.
  • В целом минибатчевый стохастический градиентный спуск быстрее стохастического и обычного градиентного спуска и менее рискован с точки зрения сходимости.
