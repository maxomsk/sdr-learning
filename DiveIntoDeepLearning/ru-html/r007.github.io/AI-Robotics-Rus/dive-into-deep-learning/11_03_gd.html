Погружение в глубокое обучение

11.3 Градиентный спуск

Хотя градиентный спуск (gradient descent) редко применяют в глубоком обучении напрямую, понимание этого метода — ключ к пониманию алгоритма стохастического градиентного спуска из следующего раздела. Например, из-за слишком большой скорости обучения задача оптимизации может расходиться; это явление уже проявляется в градиентном спуске. Аналогично, предобусловливание (preconditioning) — распространённый приём в градиентном спуске, который переносится и на более совершенные алгоритмы. Начнём с простого одномерного случая.

11.3.1 Одномерный градиентный спуск

Почему алгоритм градиентного спуска может оптимизировать целевую функцию? Одномерный градиентный спуск даёт хорошее представление об этом. Рассмотрим класс непрерывно дифференцируемых вещественных функций f:R→R. С помощью разложения в ряд Тейлора получаем

f(x+ϵ)=f(x)+ϵf′(x)+O(ϵ2).(11.3.1)

То есть в первом приближении f(x+ϵ) определяется значением функции f(x) и её первой производной f′(x) в точке x. Можно предположить, что при движении в направлении антеградиента на малую величину ϵ значение f уменьшится. Для простоты выберем фиксированный шаг η>0 и положим ϵ=−ηf′(x). Подставив это в разложение Тейлора, получим

f(x−ηf′(x))=f(x)−ηf′2(x)+O(η2f′2(x)).(11.3.2)

Если производная f′(x)=0 не обращается в нуль, мы можем продолжать разложение, поскольку ηf′2(x)>0. Кроме того, мы всегда можем выбрать η достаточно малым, чтобы члены более высокого порядка стали пренебрежимо малы. Поэтому

f(x−ηf′(x))⪅f(x).

Это означает, что если итеративно обновлять x по правилу

x←x−ηf′(x),

то значение функции f(x), скорее всего, будет уменьшаться. Таким образом, в градиентном спуске мы сначала выбираем начальное значение x и константу η>0, а затем итеративно обновляем x до выполнения условия остановки — например, когда модуль градиента ∣f′(x)∣ становится достаточно малым или когда число итераций достигает заданного значения.

Покажем, как реализовать градиентный спуск. Для простоты возьмём целевую функцию f(x)=x2. Хотя мы знаем, что f(x) достигает минимума при x=0, мы всё же используем эту простую функцию, чтобы наблюдать за изменением x.

Далее возьмём x=10 в качестве начального значения и предположим, что η=0.2. Применив градиентный спуск к x на 10 итераций, мы увидим, что значение x в конце концов приблизится к оптимальному решению.

MXNet, PyTorch, TensorFlow:

def gd(eta, f_grad):
    x = 10.0
    results = [x]
    for i in range(10):
        x -= eta * f_grad(x)
        results.append(float(x))
    print(f'эпоха 10, x: {x:f}')
    return results

results = gd(0.2, f_grad)

11.3.1.1 Скорость обучения

Скорость обучения (learning rate) определяет, сойдётся ли целевая функция к локальному минимуму и когда это произойдёт. Скорость обучения η задаёт разработчик алгоритма. Заметим, что если выбрать слишком маленькую скорость обучения, обновления x будут очень медленными, и понадобится больше итераций. Например, рассмотрим ход той же задачи оптимизации при η=0.05. Как видно ниже, даже за 10 шагов мы всё ещё далеки от оптимального решения.

show_trace(gd(0.05, f_grad), f)

Напротив, если выбрать слишком большую скорость обучения, ∣ηf′(x)∣ может оказаться слишком большим для линейного приближения первого порядка. То есть член O(η2f′2(x)) в формуле (11.3.2) может стать существенным. В этом случае итерации по x уже не гарантируют уменьшения f(x). Например, при η=1.1 значение x перескакивает оптимальное решение x=0 и постепенно расходится.

show_trace(gd(1.1, f_grad), f)

11.3.1.2 Локальные минимумы

Чтобы продемонстрировать градиентный спуск для невыпуклой функции, рассмотрим функцию f(x)=x⋅cos(cx), где c — некоторая константа. Эта функция имеет бесконечно много локальных минимумов. В зависимости от выбранной скорости обучения мы в итоге можем получить лишь одно из многих решений. Следующий пример показывает, как (нереалистично) большая скорость обучения приводит к худшему локальному минимуму.

c = d2l.tensor(0.15 * np.pi)

def f(x):  # Целевая функция
    return x * d2l.cos(c * x)

def f_grad(x):  # Градиент целевой функции
    return d2l.cos(c * x) - c * x * d2l.sin(c * x)

show_trace(gd(2, f_grad), f)

11.3.2 Многомерный градиентный спуск

Теперь, когда одномерный случай понятен, рассмотрим x=[x1​,x2​,…,xd​]⊤. То есть целевая функция f:Rd→R отображает вектор в скаляр. Соответственно, её градиент тоже многомерный: это вектор из d частных производных:

∇f(x)=[∂x1​∂f(x)​,∂x2​∂f(x)​,…,∂xd​∂f(x)​]⊤.

Каждый элемент градиента ∂f(x)/∂xi​ показывает скорость изменения f в точке x по входу xi​. Как и в одномерном случае, для многомерных функций можно использовать соответствующее разложение Тейлора. А именно,

f(x+ϵ)=f(x)+ϵ⊤∇f(x)+O(∥ϵ∥2).(11.3.3)

Иными словами, с точностью до членов второго порядка по ϵ направление наибыстрейшего убывания задаёт антеградиент −∇f(x). Выбрав подходящую скорость обучения η>0, получаем типичный алгоритм градиентного спуска:

x←x−η∇f(x).

Как этот алгоритм работает на практике? Рассмотрим целевую функцию f(x)=x12​+2x22​ с двумерным вектором x=[x1​,x2​]⊤ на входе и скаляром на выходе. Градиент задаётся формулой ∇f(x)=[2x1​,4x2​]⊤. Мы будем наблюдать траекторию x при градиентном спуске из начальной точки [−5,−2].

Нам понадобятся две вспомогательные функции: первая — это функция update, которую мы применим к начальному значению 20 раз; вторая — функция, которая отображает траекторию x.

MXNet, PyTorch, TensorFlow:

def train_2d(trainer, steps=20, f_grad=None):  #@save
    """Оптимизация 2D-целевой функции с помощью пользовательского тренера"""
    # s1 и s2 — внутренние переменные состояния, которые будут использованы позже
    x1, x2, s1, s2 = -5, -2, 0, 0
    results = [(x1, x2)]
    for i in range(steps):
        if f_grad:
            x1, x2, s1, s2 = trainer(x1, x2, s1, s2, f_grad)
        else:
            x1, x2, s1, s2 = trainer(x1, x2, s1, s2)
        results.append((x1, x2))
    print(f'эпоха {i + 1}, x1: {float(x1):f}, x2: {float(x2):f}')
    return results

11.3.3 Адаптивные методы

Как мы видели в разделе 11.3.1.1, выбрать «правильную» скорость обучения η непросто. Если её выбрать слишком маленькой, прогресса почти не будет; если слишком большой — решение начнёт колебаться и может даже расходиться. А что, если бы мы могли определять η автоматически или вообще не выбирать скорость обучения? Выход может дать метод второго порядка, который учитывает не только значение и градиент целевой функции, но и её кривизну. Хотя из-за вычислительных затрат такие методы напрямую неприменимы в глубоком обучении, они дают полезную интуицию для построения продвинутых алгоритмов оптимизации, которые могут воспроизводить многие желаемые свойства описанных ниже алгоритмов.

11.3.3.1 Метод Ньютона

Вспомним разложение Тейлора для функции f:Rd→R. Фактически его можно записать так:

f(x+ϵ)=f(x)+ϵ⊤∇f(x)+21​ϵ⊤∇2f(x)ϵ+O(∥ϵ∥3).(11.3.4)

Чтобы не громоздить обозначения, определим H=def∇2f(x) как гессиан f; это матрица размера d×d. Для малых d и простых задач H вычислить легко. Однако для глубоких нейронных сетей H может быть очень большой: хранение O(d2) элементов обходится дорого, а вычисление через обратное распространение может сделать ситуацию ещё хуже. Тем не менее пока отвлечёмся от этих соображений и посмотрим, какой алгоритм из этого получится.

В конце концов, минимум f удовлетворяет условию ∇f=0. Следуя правилам математического анализа из раздела 2.4, возьмём производную от ϵ по выражению (11.3.4) и отбросим несущественные члены высшего порядка. В результате получаем

∇f(x)+Hϵ=0 и, следовательно, ϵ=−H−1∇f(x).

То есть в рамках задачи оптимизации нам нужно обратить гессиан H.

Для простого примера f(x)=21​x2 имеем ∇f(x)=x и H=1. Поэтому для любого x получаем ϵ=−x. Иными словами, для идеальной сходимости достаточно одного шага без каких-либо настроек. Здесь нам повезло: разложение Тейлора точное, так как f(x+ϵ)=21​x2+ϵx+21​ϵ2.

Рассмотрим другие задачи. Пусть задана выпуклая функция c(x)=cosh(cx) (гиперболический косинус), где c — некоторая константа. Видно, что после нескольких итераций мы получаем глобальный минимум в точке x=0.

c = d2l.tensor(0.5)

def f(x):  # Целевая функция
    return d2l.cosh(c * x)

def f_grad(x):  # Градиент целевой функции
    return c * d2l.sinh(c * x)

def f_hess(x):  # Гессиан целевой функции
    return c**2 * d2l.cosh(c * x)

def newton(eta=1):
    x = 10.0
    results = [x]
    for i in range(10):
        x -= eta * f_grad(x) / f_hess(x)
        results.append(float(x))
    print('эпоха 10, x:', x)
    return results

show_trace(newton(), f)

Теперь рассмотрим невыпуклую функцию, например f(x)=xcos(cx), где c — некоторая константа. Обратите внимание: в методе Ньютона в конце концов мы делим на гессиан. Это значит, что если вторая производная отрицательна, значение f может начать расти. Это фатальный недостаток алгоритма! Посмотрим, что происходит на практике.

c = d2l.tensor(0.15 * np.pi)

def f(x):  # Целевая функция
    return x * d2l.cos(c * x)

def f_grad(x):  # Градиент целевой функции
    return d2l.cos(c * x) - c * x * d2l.sin(c * x)

def f_hess(x):  # Гессиан целевой функции
    return - 2 * c * d2l.sin(c * x) - x * c**2 * d2l.cos(c * x)

show_trace(newton(), f)

Результат получился катастрофическим. Как это исправить? Один из способов — заменить гессиан его абсолютным значением; другая стратегия — снова ввести скорость обучения. Это может показаться противоречащим исходной идее, но это не совсем так: знание второго порядка позволяет быть осторожным там, где кривизна велика, и использовать большую скорость обучения там, где целевая функция более пологая. Посмотрим, как это работает при несколько меньшей скорости обучения, например η=0.5. Как видим, получился довольно эффективный алгоритм.

show_trace(newton(0.5), f)

11.3.3.2 Анализ сходимости

Здесь мы на примере некоторых выпуклых функций f проанализируем скорость сходимости метода Ньютона. Эти функции трижды дифференцируемы, а вторая производная не равна нулю, то есть f′′>0. Поскольку доказательство для многомерного случая является прямым обобщением доказательства для приведённого ниже одномерного случая и не добавляет понимания задачи, мы опускаем многомерный случай.

Обозначим через x(k) значение x на k-й итерации, а через e(k)=defx(k)−x∗ — расстояние до оптимальности на k-й итерации. Разложив в ряд Тейлора, получаем, что условие f′(x∗)=0 можно записать в виде

0=f′(x(k)−e(k))=f′(x(k))−e(k)f′′(x(k))+21​(e(k))2f′′′(ξ(k)),

где ξ(k)∈[x(k)−e(k),x(k)]. Разделив это разложение на f′′(x(k)), получаем

e(k)−f′′(x(k))f′(x(k))​=21​(e(k))2f′′(x(k))f′′′(ξ(k))​.

Вспомним предыдущее уравнение обновления x(k+1)=x(k)−f′(x(k))/f′′(x(k)). Подставив его и взяв модули обеих частей, получаем

​e(k+1)​=21​(e(k))2f′′(x(k))​f′′′(ξ(k))​​.

Следовательно, всякий раз, когда мы находимся в ограниченной области, где ​f′′′(ξ(k))​/(2f′′(x(k)))≤c, ошибка убывает квадратично:

​e(k+1)​≤c(e(k))2.

С другой стороны, специалисты по оптимизации называют сходимость «линейной» при условии ​e(k+1)​≤α​e(k)​, а при этом говорят о «постоянной» скорости сходимости. Заметим, что скорость сходимости в целом оценить нельзя, но как только мы оказываемся вблизи минимума, сходимость становится очень быстрой. Кроме того, такой анализ требует, чтобы f хорошо вела себя при высоких порядках производных, то есть чтобы f не обладала какими-либо «экстремальными» свойствами в том, как быстро меняется её значение.

11.3.3.3 Предобусловливание

Вычислять и хранить полный гессиан очень дорого, и один из способов смягчить эту проблему — «предобусловливание». Оно позволяет обойтись без вычисления всего гессиана и учитывает только его «диагональные» элементы; алгоритм обновляется по формуле:

x←x−ηdiag(H)−1∇f(x).

Это не так точно, как полный метод Ньютона, но всё же гораздо лучше, чем обходиться без него. Почему предобусловливание работает? Представьте, что одна переменная измеряет высоту в миллиметрах, а другая — в километрах. Если оба естественных масштаба выражены в метрах, наша параметризация сильно рассогласована. К счастью, предобусловливание устраняет это несоответствие. Эффективное предобусловливание градиентного спуска равносильно выбору разной скорости обучения для каждой координаты вектора x. Мы увидим в одном из следующих разделов, что предобусловливание стимулировало ряд новшеств в алгоритмах стохастического градиентного спуска.

11.3.3.4 Градиентный спуск и линейный поиск

Одна из ключевых проблем градиентного спуска в том, что можно перескочить цель или продвигаться слишком медленно. Простое решение этой проблемы — комбинировать линейный поиск с градиентным спуском. А именно, мы используем направление, заданное ∇f(x), и затем проводим двоичный поиск, чтобы определить такую скорость обучения η, при которой f(x−η∇f(x)) принимает минимальное значение.

С точки зрения анализа и доказательств этот алгоритм сходится быстро (см. Boyd and Vandenberghe, 2004). Однако для глубокого обучения он малопригоден, поскольку каждый шаг линейного поиска требует вычисления целевой функции на всём наборе данных, и такой способ реализации слишком дорог.

Резюме

  • Величина скорости обучения важна: слишком большая скорость приводит к расходимости модели, слишком малая — к отсутствию прогресса.
  • Градиентный спуск может застрять в локальном минимуме и не найти глобальный минимум.
  • В моделях высокой размерности настроить скорость обучения сложно.
  • Предобусловливание помогает выравнивать масштабы.
  • В выпуклых задачах метод Ньютона, как только начинает работать корректно, сходится гораздо быстрее.
  • Для невыпуклых задач не следует применять метод Ньютона без дополнительных настроек.

Упражнения

  1. Проведите эксперименты с градиентным спуском при разных скоростях обучения и разных целевых функциях.
  2. Реализуйте линейный поиск на отрезке [a,b] для минимизации выпуклой функции.
    1. Нужны ли производные для двоичного поиска, то есть для выбора между [a,(a+b)/2] и [(a+b)/2,b]?
    2. Насколько быстро сходится алгоритм?
    3. Реализуйте этот алгоритм и примените его для нахождения минимума log(exp(x)+exp(−2x−3)).
  3. Постройте целевую функцию, определённую на R2, для которой градиентный спуск будет очень медленным. Подсказка: масштабы разных координат должны различаться.
  4. Реализуйте облегчённую версию метода Ньютона с предобусловливанием.
    1. Используйте диагональный гессиан в качестве предобусловливателя.
    2. Используйте его абсолютное значение вместо фактического (возможно, со знаком).
    3. Примените это к задаче выше.
  5. Примените описанный алгоритм к нескольким целевым функциям (выпуклым и невыпуклым). Что будет, если повернуть координаты на 45 градусов?
